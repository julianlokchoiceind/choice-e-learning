# Details:
This task involves implementing the newly created LoadingState component across all specified admin and public pages. The implementation should follow these guidelines:

1. For each page listed in the requirements, identify the appropriate loading state variant (default, page, table, section, or button) based on the page's context and content.

2. Admin Pages Implementation:
   - Replace existing loading indicators in all 20 admin pages with the new LoadingState component
   - Use the 'page' variant for full page loading states
   - Use the 'table' variant for data table loading states (especially in list views)
   - Use the 'section' variant for partial page content loading
   - Use the 'button' variant for action button loading states

3. Public Pages Implementation:
   - Replace existing loading indicators in all 12 public pages with the new LoadingState component
   - Apply appropriate variants based on the page context
   - Ensure consistent user experience across marketing, auth, dashboard, and course pages

4. Implementation Considerations:
   - Ensure the LoadingState component is imported correctly from its location
   - Pass the appropriate variant prop to each LoadingState instance
   - Maintain existing conditional logic that determines when loading states should be shown
   - Ensure the spinner color uses the --spinner-color CSS variable defined in Task #3

5. Code Structure:
   - Follow the existing pattern for loading state implementation
   - Ensure loading states are properly integrated with data fetching logic
   - Maintain accessibility standards when implementing loading indicators

This task depends on the completion of Task #2 (Update LoadingState Component) and Task #3 (Add CSS Variable for Spinner Color).

# Test Strategy:
To verify the successful implementation of this task, follow these testing steps:

1. Manual Visual Inspection:
   - Navigate to each of the 32 pages listed in the requirements
   - Verify that the appropriate LoadingState component is visible during loading
   - Confirm that the correct variant is used based on the context of each page
   - Check that the spinner color matches the --spinner-color CSS variable

2. Functionality Testing:
   - Test each page under various network conditions (throttled network, etc.)
   - Verify that loading states appear and disappear at appropriate times
   - Ensure that loading states don't interfere with user interactions once content is loaded

3. Code Review:
   - Verify that all 32 files have been updated to use the new LoadingState component
   - Confirm that appropriate variant props are passed to each LoadingState instance
   - Check that imports are correct and no console errors are present

4. Cross-browser Testing:
   - Test the loading states in Chrome, Firefox, Safari, and Edge
   - Verify consistent appearance and behavior across browsers

5. Responsive Testing:
   - Test loading states on mobile, tablet, and desktop viewports
   - Ensure loading indicators are appropriately sized and positioned on all devices

6. Accessibility Testing:
   - Verify that loading states are announced properly to screen readers
   - Check that loading indicators meet contrast requirements
   - Ensure that loading states don't cause layout shifts that would impact user experience

Document any issues found during testing with screenshots and detailed descriptions.

## Phân tích và Kế hoạch triển khai LoadingState

Sau khi rà soát mã nguồn và tài liệu PRD, tôi đã xác định các trang cần triển khai LoadingState và phương án triển khai phù hợp cho từng trang.

### Các variant LoadingState hiện có:

1. **default**: Spinner đơn giản, thích hợp cho các trường hợp chung
2. **page**: Spinner toàn trang, overlay trên nền mờ, thích hợp cho trang đang tải
3. **table**: Spinner với các dòng giả lập, thích hợp cho bảng dữ liệu đang tải
4. **section**: Spinner trong khung hình chữ nhật, thích hợp cho một phần của trang
5. **button**: Spinner nhỏ trong nút, thích hợp cho các thao tác đang xử lý
